# 중간발표 예상 질문 답변

이 문서는 중간발표에서 받을 가능성이 높은 질문에 대비하기 위한 답변 초안이다. 답변 원칙은 세 가지다.

- 현재 확인 가능한 숫자만 말한다.
- 단정적인 표현보다 기준 선택의 trade-off를 설명한다.
- 부족한 부분은 숨기지 말고 최종발표 보강 계획으로 연결한다.

## 1. 프로젝트 정의

### Q1. 이 프로젝트는 churn 예측인가요, 재구매 지연 예측인가요?

재구매 지연 위험 예측에 가깝습니다. Instacart 데이터에는 실제 탈퇴 여부나 장기간 미방문 이후의 확정 churn 라벨이 없기 때문에, 본 프로젝트에서는 고빈도 고객의 다음 주문 간격이 길어지는지를 `delay_risk`로 정의했습니다.

발표 답변:

> 이 프로젝트는 엄밀한 의미의 churn 예측이라기보다, 고빈도 고객의 다음 주문이 지연될 위험을 예측하는 문제로 정의했습니다. Instacart에는 실제 탈퇴 라벨이 없으므로 `target_gap`을 이용해 재구매 지연 위험을 만들었습니다.

### Q2. 왜 고빈도 고객만 대상으로 했나요?

Instacart에는 구매 금액이 없으므로 고가치 고객을 직접 정의하기 어렵습니다. 대신 반복 구매 이력이 충분한 고객을 고빈도 고객으로 정의하면 주문 간격과 최근 패턴을 안정적으로 계산할 수 있습니다.

발표 답변:

> 구매 금액 정보가 없어 고가치 고객을 직접 정의하기 어렵기 때문에, 총 주문 횟수 상위 20%를 고빈도 고객으로 정의했습니다. 현재 데이터 기준 threshold는 24회이며, 최종 모델링 샘플은 42,499명입니다.

## 2. 라벨 기준

### Q3. 왜 `target_gap > 15`를 지연 위험으로 봤나요?

현재 최종 모델링 데이터에서 고빈도 고객의 `target_gap` 분위수는 `q80 = 15`, `q90 = 24`, `q95 = 30`이다. 따라서 15일은 q90이 아니라 q80 수준의 조기탐지 기준이다.

발표 답변:

> 현재는 조기 위험 탐지를 우선하기 위해 q80 수준인 15일을 운영 라벨 기준으로 사용했습니다. 즉 `target_gap > 15`이면 delay risk로 정의했습니다. 다만 q90 기준인 24일도 더 엄격한 고위험 기준이 될 수 있어, q90 기준 sensitivity analysis도 함께 수행했습니다.

### Q4. q90 기준인 24일을 쓰는 게 더 맞지 않나요?

가능한 대안이다. q90 기준은 더 엄격한 고위험 지연을 정의하지만, 양성 비율이 `18.65%`에서 `9.90%`로 줄어든다. 이 경우 F1-score가 낮아지고 Recall/F1 해석이 더 민감해진다.

발표 답변:

> 맞습니다. q90인 24일은 더 엄격한 고위험 기준으로 볼 수 있습니다. 그래서 `target_gap > 24` 기준도 비교했습니다. q90 기준에서는 양성 비율이 9.90%로 줄고 F1 기준 best model은 LightGBM이었지만, F1은 0.4140으로 낮아졌습니다. 중간발표에서는 q80 기준을 기본으로 두고, 최종 기준은 교수님 피드백을 받아 확정하려고 합니다.

## 3. 전처리와 누수

### Q5. 데이터 누수는 없나요?

현재 구조에서 핵심은 feature와 label의 시점을 분리한 것이다. target 주문은 label 생성에만 사용하고, feature는 target 이전 주문 이력만으로 만든다.

발표 답변:

> target 주문은 `target_gap` 라벨 생성에만 사용했습니다. 입력 feature는 target 주문 이전 이력에서 만든 집계값입니다. 따라서 label이 되는 target 주문 이후 정보는 feature에 들어가지 않도록 설계했습니다.

### Q6. 왜 time split이 아니라 random split인가요?

현재 `model_base_hv.csv`는 사용자당 1행만 있는 최종 집계 테이블이다. 고객별 여러 시점 샘플이 없으므로 고객 내부 시간 흐름을 나누는 time-aware split을 적용하기 어렵다. 대신 사용자당 1행이므로 stratified random split은 user-level split으로 해석할 수 있다.

발표 답변:

> 현재 모델링 테이블은 고객당 1개의 target 샘플만 포함합니다. 그래서 고객 내부의 여러 시점을 train/test로 나누는 time-aware split은 현재 구조에서는 적용하기 어렵습니다. 대신 사용자당 1행이므로 같은 고객이 여러 split에 중복되지는 않습니다. 더 엄밀한 time-aware split은 고객별 여러 target 시점을 생성하는 추가 전처리가 필요해서 최종발표 보강 과제로 보고 있습니다.

## 4. 모델 비교

### Q7. 왜 MLP만 쓰지 않고 Tree Boosting도 추가했나요?

현재 데이터는 주문 sequence가 아니라 사용자 단위 집계 feature로 구성된 tabular 데이터다. 이런 데이터에서는 LightGBM, XGBoost, CatBoost 같은 Tree Boosting 계열이 강한 baseline이므로 MLP와 함께 비교하는 것이 더 공정하다.

발표 답변:

> 현재 입력은 sequence가 아니라 집계형 tabular feature입니다. 따라서 MLP만 비교하면 baseline이 약할 수 있어 LightGBM, XGBoost, CatBoost를 추가했습니다. 결과적으로 Tree Boosting 계열이 MLP보다 근소하게 안정적인 성능을 보였습니다.

### Q8. 최종 모델은 무엇인가요?

중간발표 단계에서는 최종 모델을 과하게 단정하지 않는다. F1과 ROC-AUC 기준으로는 CatBoost가 근소하게 앞섰고, Recall 기준으로는 LightGBM이 높으며, MLP도 유사한 수준의 성능을 보였다.

발표 답변:

> 현재 tabular 실험에서는 CatBoost가 F1-score와 ROC-AUC 기준에서 가장 균형적인 결과를 보였고, LightGBM은 Recall이 가장 높았습니다. 다만 차이가 크지 않기 때문에 최종 모델을 단정하기보다는, Tree Boosting 계열이 강한 baseline으로 작동했고 MLP도 경쟁력 있는 대안이라고 해석했습니다.

### Q9. LSTM은 왜 최종 비교에서 약하게 다루나요?

현재 데이터는 사용자당 1행의 집계 feature이므로 실제 주문 sequence가 아니다. 기존 LSTM 결과는 feature vector를 pseudo-sequence로 변환한 참고 실험에 가깝다.

발표 답변:

> LSTM은 원래 최근 주문 흐름을 직접 보는 모델로 설계하고 싶었지만, 현재 기준 데이터는 사용자당 1행의 집계 feature입니다. 그래서 현재 LSTM 결과는 실제 주문 sequence 기반 결과로 보기 어렵습니다. 중간발표에서는 확장 방향으로 제시하고, 최종발표에서 sequence pipeline을 보강하는 방향이 안전하다고 판단했습니다.

## 5. 평가 지표

### Q10. 왜 accuracy를 중심으로 보지 않나요?

양성 비율이 q80 기준에서도 `18.65%`이고 q90 기준에서는 `9.90%`로 더 낮아진다. 이런 불균형 데이터에서는 다수 클래스를 맞히는 것만으로 accuracy가 높아질 수 있다.

발표 답변:

> 지연 위험 고객이 소수 클래스이기 때문에 accuracy만 보면 위험 고객을 놓치는 모델도 좋아 보일 수 있습니다. 그래서 Recall, F1-score, ROC-AUC, Average Precision을 함께 봤습니다.

### Q11. 왜 threshold tuning을 했나요?

모델의 예측 확률을 어떤 기준으로 0/1로 나눌지에 따라 Recall과 Precision이 크게 달라진다. 중간발표 실험에서는 validation set에서 F1-score가 최대가 되는 threshold를 선택했다.

발표 답변:

> 위험 고객 탐지에서는 threshold가 중요합니다. threshold를 낮추면 더 많이 잡지만 FP가 늘고, 높이면 precision은 좋아질 수 있지만 놓치는 고객이 늘어납니다. 그래서 validation set에서 F1-score 기준으로 threshold를 선택했습니다.

## 6. 결과 해석

### Q12. 모델별 강점은 어떻게 다르나요?

현재 q80 기준 tabular 비교 결과:

| 관점 | 모델 | 값 |
| --- | --- | ---: |
| F1-score | CatBoost | 0.5105 |
| Recall | LightGBM | 0.7157 |
| ROC-AUC | CatBoost | 0.8226 |
| Average Precision | XGBoost | 0.4807 |
| MLP F1-score | MLP | 0.5064 |

발표 답변:

> CatBoost는 F1과 ROC-AUC 기준에서 균형적이었고, LightGBM은 Recall이 가장 높아 위험 고객을 넓게 포착했습니다. XGBoost는 Average Precision이 가장 높았습니다. MLP는 Tree Boosting보다 약간 낮지만 큰 차이는 아니어서, 집계 feature 기반 신경망 대안으로 볼 수 있습니다.

### Q13. 틀린 예측은 어떤 패턴이었나요?

CatBoost 오류 분석 기준, TP는 FN보다 `last_gap_before_target`, `recent_3_avg_gap`, `recent_5_avg_gap`, `gap_trend`가 높게 나타났다. 즉 최근 주문 간격이 이미 길어진 고객은 잘 잡았지만, 실제 target 주문은 지연됐어도 직전/최근 gap 신호가 약한 고객은 놓칠 수 있다.

발표 답변:

> 오류 분석을 보면 최근 주문 간격이 이미 길어진 고객은 모델이 비교적 잘 탐지했습니다. 반대로 실제 target 주문은 지연됐지만 직전/최근 gap 신호가 약한 고객은 FN으로 남을 가능성이 있었습니다. 이 결과는 인과관계라기보다 모델이 어떤 feature 신호에 반응했는지 보는 해석 자료로 사용했습니다.

## 7. 한계와 보강 계획

### Q14. 현재 프로젝트의 가장 큰 한계는 무엇인가요?

- 현재 기준 데이터는 사용자당 1행 집계 feature라 실제 sequence 모델 비교가 부족하다.
- calendar date 기준 time split이 아니다.
- 라벨 기준은 q80과 q90 중 최종 선택이 필요하다.
- Instacart에는 구매 금액 정보가 없어 고가치 고객이 아니라 고빈도 고객으로 정의했다.

발표 답변:

> 현재 가장 큰 한계는 실제 주문 sequence pipeline이 아직 충분히 복원되지 않았다는 점입니다. 그래서 중간발표에서는 tabular 모델 비교를 중심으로 정리했고, LSTM은 최종발표 확장 방향으로 두었습니다. 또한 q80 기준과 q90 기준 중 어떤 라벨이 더 적절한지는 교수님 피드백을 받아 최종 확정하려고 합니다.
